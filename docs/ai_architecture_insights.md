# Архитектурные идеи из SmartNotes для CoreAsset

Исследования из папки `SmartNotes-ai` описывают продвинутые паттерны создания надежных и быстрых Progressive Web Apps. Несмотря на разницу в бизнес-логике, часть этих концепций можно точечно внедрить в систему управления активами `CoreAsset`.

## 1. Решение проблемы "плохого Wi-Fi в подвале" (Offline Queue)
В `CoreAsset` инженеры техподдержки и АХЧ часто работают на выездах, складах или в серверных, где интернет может обрываться. 
**Как в исследовании:** Использование `localforage` (IndexedDB) и фонового `Sync Engine`, который перехватывает событие `online`.
**Как адаптировать для нас:**
- Вместо полного перевода всего приложения на `React Query` (что потребовало бы переписать все Server Actions), мы можем сделать **"Умные формы"** (Smart Forms).
- Если ИТ-специалист закрывает инцидент или меняет статус устройства, а сеть пропала, мы перехватываем ошибку сети (в `isLikelyNetworkError`).
- Сохраняем мутацию (закрытие тикета) в `IndexedDB` (очередь `offlineStore`).
- Когда телефон/ноутбук ловит сеть (срабатывает событие `window.addEventListener("online")`), скрытый провайдер `SyncProvider` автоматически отправляет накопившиеся изменения в Supabase.

## 2. Безопасное обновление PWA без "залипаний" (Service Worker Lifecycle)
В `CoreAsset` мы недавно добавили `PWARegister.tsx`.
**Проблема из исследования:** Браузеры склонны кешировать Service Worker и старые файлы. Если мы выкатим обновление `CoreAsset`, у части сотрудников портал будет работать по-старому, пока они не закроют все вкладки.
**Как адаптировать для нас:**
- Дополнить `sw.js` и `PWARegister.tsx` обработчиками событий `updatefound` и `controllerchange`.
- При выходе новой версии приложения выводить пользователю (поверх экрана) небольшую плашку (Toast): *"Доступна новая версия системы. Нажмите, чтобы обновить"*.
- Это гарантирует, что ИТ-отдел всегда работает с актуальной версией UI и схемой базы данных.

## 3. Hydration-Safe кеширование списков (IndexedDB Cache)
**Как в исследовании:** Хук `useHydratedOfflineData` и Skeleton-загрузчики.
**Как адаптировать для нас:**
- Сейчас `CoreAsset` загружает весь список устройств (devices) и сотрудников (employees) каждый раз при открытии диалогового окна "Новый инцидент". Это может стать медленным при тысячах устройств.
- Мы можем кешировать справочники (сотрудники, кабинеты, базовые модели устройств) в `IndexedDB` на клиенте.
- Использовать паттерн из исследования, чтобы рендерить UI моментально из локального кеша (Skeleton -> Local Cache -> Background Fetch), не вызывая ошибок гидратации Next.js (`Hydration Mismatch`).

## Что внедрить в первую очередь?

Я рекомендую не брать всё сразу, а начать с самого критичного для бизнес-процесса:
1. **PWA Update Prompt:** Улучшить регистрацию Service Worker, чтобы пользователи гарантированно получали новые фичи.
2. **Офлайн-очередь для статусов инцидентов:** Сделать так, чтобы перевод тикета в статус "Решён" работал даже без интернета (сохранялся локально и отправлялся при появлении сети).

*Эти задачи можно зафиксировать в `tech_debt.md` или оформить как новые фичи на следующий спринт.*
